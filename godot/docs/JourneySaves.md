# 旅程存档与恢复

Spring Haven 使用命名多旅程存档，避免“新旅程”覆盖上一段生活。正式文件位于 Godot
用户目录的 `SpringHaven/saves/`：

```text
saves/
  index.json
  <save_id>.json
  <save_id>.json.bak
```

`index.json` 只保存旅程名称、当前槽位、时间、当前角色、消息数量、归档状态和恢复类型。
角色属性、当前会话快照与生活日程保存在对应的 `<save_id>.json`；聊天归档和 Companion
Core 的 Heartloom 数据也使用同一个 `save_id` 分区。

## 用户操作

主菜单“📚 旅程档案”支持搜索、新建、载入、重命名、归档和恢复：

- 新建旅程前先原子保存当前旅程，再生成新的 `save_id`；
- 载入旅程会恢复角色、属性、即时聊天和生活日程，并同步 Companion Core；
- 归档只隐藏非当前旅程，不删除槽位文件、聊天归档或 Heartloom；
- 当前正在使用的旅程不能归档；
- 每次写入先生成临时文件，并保留上一版 `.bak`。

旧版 `default.json` 会自动迁移成独立槽位，原文件保留，不在迁移中删除。

## 部分恢复

如果历史上的单槽存档已经覆盖，但跨天聊天归档仍存在，旅程档案会按旧 `save_id` 显示
“可恢复的旧旅程”。恢复会：

1. 取回最近的聊天快照并创建 `conversation_only` 槽位；
2. 保持当前旅程不变，不自动切换；
3. 重新关联同 `save_id` 的 Heartloom 对话事件和长期记忆；
4. 使用当前版本的默认角色属性、里程碑和生活日程。

第 4 点是明确的数据边界：已经被历史单槽覆盖的旧属性与生活日程没有可靠来源，系统不会
伪造数值或从聊天文本猜测。部分恢复槽位会在 UI 中持续显示标记。

## 隔离规则

聊天归档界面默认只查询当前 `save_id`。普通对话、括号内容、双角色回复与后台消息可以在
同一旅程内共享可见，但不会出现在另一旅程的聊天归档中。Heartloom 和离线生活消息遵循
同一分区规则。
