# 2D / 3D 角色表现架构

Spring Haven 的产品核心不是某一种渲染形式，而是持续存在的 AI 角色。对话编排、Persona、Heartloom 记忆、RAG、生活状态、关系与自主决策都由 Companion Core 和 Godot 领域层维护；2D 与 3D 只负责把同一份角色状态表现出来，并执行经过约束的高层动作。

## 共用角色状态

表现层只读取稳定的角色视图状态：

- `role_id`、当前说话者与回复目标；
- 情绪、思考、说话、疲劳和生活需求；
- 当前互动及其阶段；
- LLM 产生的受控高层动作，例如靠近、跟随、坐下、取物和使用物品。

表现层不直接改写记忆、Persona 或模型消息，也不自行决定属性变化。用户在 2D 或 3D 中触发同一种互动，必须进入相同的互动规则与事件记录流程。

## 当前 2D 路径

`PortraitRig2D` 是现有的 2D 表现适配器。它支持：

- 分层立绘 manifest；
- 眨眼、视线跟随、呼吸和轻微摇摆；
- 文本或 TTS 音量驱动的口型；
- neutral、happy、worried、angry、shy、tired、thinking 表情；
- 生活状态驱动的表情变化。

正式 Live2D 接入时，应新增一个实现相同调用面的适配器，而不是修改聊天请求或 Core 协议。最低能力面保持为：

```text
set_role(role_id)
set_expression(expression)
set_thinking(active)
set_body_state(state)
speak(text, duration)
set_tts_mouth_level(level)
```

这样在没有 Live2D SDK、模型授权或运行时插件时，分层立绘适配器仍是可发布的回退方案。

## 未来 3D 路径

3D 角色执行器接收语义动作，不接收逐帧方向键或任意坐标。移动由 NavigationAgent、可达区域、碰撞体、速度限制和超时恢复共同约束；LLM 只选择目标和意图。场景感知输出结构化文字，例如物体名称、可交互动作、距离、占用状态和容器内容，再交给决策层。

同一事件的执行顺序为：

```text
玩家或自主决策
  -> 受控互动 / 高层动作
  -> 2D 动画或 3D 行为执行器
  -> 属性与世界状态结算
  -> 对话上下文和 Heartloom 事件
  -> 角色回应
```

## 实施顺序

1. 以现有 2D 对话舞台完成可玩的核心循环和受众测试。
2. 接入有合法发行授权的立绘或 Live2D 模型，并实现表情、口型与动作映射。
3. 加入 TTS 时间轴和可中断语音，驱动准确口型。
4. 将互动拆成可复用的语义事件，使 2D 点击和自然语言触发得到相同结果。
5. 在 3D 中实现同一事件的行为执行器，再逐步增加寻路、物件状态和自主日程。
